# 새 가격 플랜 추가 — 나중에 이어서 할 일

작성 2026-11-02 · 관련 마이그레이션 `036_plan_copy_premium.sql` ~ `038_plan_visibility.sql`

어드민 설정의 **가격 템플릿**에서 플랜을 새로 만들 수 있게 하려던 것. 지금은
**노출/숨김만** 만들었고(038), 새 플랜 추가는 아래 이유로 미뤘다.

---

## 1. 왜 문구만 추가해서는 안 되나

플랜 넷(메인 시안·로고·디자인 전체·프로젝트)은 문구 표(`plan_copy`)만 행으로
되어 있고, 나머지는 **플랜마다 칸·코드가 따로** 박혀 있다. 새 플랜은 이 모든
자리에 자기 몫이 있어야 동작한다.

| 자리 | 지금 모양 | 새 플랜이 들어가려면 |
| --- | --- | --- |
| 디자이너가 받는지 | `designers.scope_sample` · `scope_logo` · `scope_full_design` · `scope_with_dev` (017·019·033) | 플랜마다 칸 → 행으로 |
| 디자이너별 기본 가격 | `design_price`+`price_max`(범위) · `logo_price`(보기 중 선택) · `full_design_price` · `project_price`(어드민 입력) — 플랜마다 규칙도 다르다 | 가격 방식을 플랜 속성으로 |
| 의뢰 유형 | `inquiries.inquiry_type` 에 **보이는 글자**를 저장, check 제약 `inquiries_type_allowed` 가 넷만 허용(031·033) | 제약을 풀거나 플랜 key 로 저장 |
| 코드의 유형 목록 | `src/lib/scopes.ts` 의 `SCOPES`·`SCOPE_LABELS`, `src/lib/inquiry-types.ts` 의 `INQUIRY_TYPES`·`INQUIRY_TYPE_SCOPE` 등 | DB 에서 읽은 목록으로 |
| 표의 check 제약 | `plan_copy` · `designer_premium_prices` · `designer_plan_details` · `designer_plan_options` · `option_templates.targets` 가 모두 `plan in ('sample','logo','full_design','with_dev')` | 제약 대신 플랜 표에 외래키 |
| 탐색 | 필터·"어떤 의뢰를 원하시나요?"(`scope-prompt.tsx`)가 `SCOPES` 를 돈다 | 플랜 목록을 받아 돈다 |
| 스튜디오 가격 설정 | `src/components/designers/plan-form.tsx` 가 플랜마다 다른 칸을 그린다 | 가격 방식별 칸 하나로 |

---

## 2. 정해야 할 것 (사용자 확인 필요)

1. **가격 방식** — 새 플랜의 디자이너별 가격을 어떻게 정하나.
   - (a) 어드민이 디자이너마다 최소가 입력 — 디자인 전체·프로젝트와 같음
   - (b) 디자이너가 보기 중에서 고름 — 로고와 같음
   - (c) 범위(시작가 ~ 상한) — 메인 시안과 같음
2. **누가 켜고 끄나** — 디자이너 본인도 받을지 정하나, 어드민만인가(프로젝트처럼).
3. **의뢰 폼·탐색 필터·"어떤 의뢰" 팝업**에 새 유형으로 들어가는가.

---

## 3. 권하는 구조 (행 방식 전환)

```
plans                 플랜 목록 — key, 순서, 가격 방식, 누가 켜는지, 노출
plan_copy             (있음) plan → plans.key 외래키로
designer_plans        디자이너 × 플랜 — 받는지, 기본 가격(min/max), 프리미엄 스위치·가격
```

- 기존 칸 값(`scope_*`, `*_price`, `designer_premium_prices`)은 `designer_plans` 로
  **옮겨 담는 마이그레이션**을 따로 쓴다. 옮긴 뒤 한동안 옛 칸을 남겨 두고
  화면이 새 표만 읽는 것을 확인한 다음 지운다.
- `inquiries.inquiry_type` 은 지금처럼 **보이는 글자**를 남기되(옛 문의 보존),
  새로 `plan_key` 칸을 더해 거기로 고르는 쪽이 안전하다. check 제약은 푼다.
- 노출/숨김(`plan_copy.visible`, 038)은 `plans.visible` 로 옮긴다.

---

## 4. 이미 행으로 되어 있어 그대로 쓰는 것

새 플랜이 생겨도 손댈 필요가 없다(제약만 풀면 된다).

- 플랜 이름·설명·작업 기간 — `plan_copy` (036·037)
- 유형별 프리미엄 스위치 — `plan_copy.enabled` (036)
- 포함 항목 템플릿·디자이너별 등록 — `option_templates`, `designer_plan_options` (037)
- 디자이너별 작업 기간 — `designer_plan_details` (037)

---

## 5. 작업 순서 제안

1. 2번 질문 정하기
2. `plans`·`designer_plans` 표 + 옮겨 담기 마이그레이션
3. 읽기 쪽(`site-settings.ts`·`public-designers.ts`)을 새 표로 — 화면은 그대로
4. 화면이 쓰는 `SCOPES` 상수를 DB 목록으로 하나씩 교체
   (탐색 → 상세 패널 → 의뢰 폼 → 스튜디오 → 어드민)
5. 어드민 가격 템플릿에 "플랜 추가" 버튼
6. 옛 칸·check 제약 정리

운영 배포 직후보다는 한숨 돌린 뒤에 하는 게 낫다 — 기존 데이터를 옮기는 일이라
되돌리기 어렵다.
